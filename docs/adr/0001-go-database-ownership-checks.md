# Preserve ownership checks for Go database reads

Accepted on 2026-10-07. Go will use a dedicated database role with SELECT access to profiles and floor templates, without RLS bypass or membership in the broader authenticated role. Separate role-specific SELECT policies preserve profile and charge-nurse template ownership using a transaction-local Auth user ID supplied by the server; existing client policies remain intact. This keeps database ownership protection alongside Go authorization, rather than granting the backend unrestricted row access and relying solely on Go filtering. The database trusts this server-supplied identity, so token verification remains mandatory before handling user requests; the setting protects against missing filters, not stolen backend credentials.

Development preflight found five workflow functions with EXECUTE granted to PUBLIC. The role migration removes those blanket grants while retaining explicit existing anon/authenticated/service_role grants, so the Go reader cannot inherit unrelated privileged workflows. It was applied to development on 2026-10-08, verified through live Go ownership tests, and registered in CLI migration history on 2026-10-10.
